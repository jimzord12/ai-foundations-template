# Agent layout, template permissions and dogfood manifest

## Context and Problem Statement

Generated projects needed a place for agent profiles and shared skills, a permission file that lets routine work run without prompts, and this repo needed to use the same profiles and skills without letting its copies drift. TASK-24.

## Considered Options

- Permissions: the owner's narrow allowlist (answer 5 in 0021, amended by 0024), or the permissive policy this repo adopted in 0027.
- Dogfooding: symlinks, a sync script with a manifest, or hand-copying.

## Decision Outcome

- **Layout:** `.claude/agents/<name>.md` holds thin one-job profiles that preload shared skills from `.claude/skills/<name>/SKILL.md` with the `skills` field; documented in `docs/protocols/agents.md` with the frontmatter fields checked against the Claude Code docs on 2026-10-02.
- **Template permissions:** chosen option "the owner's narrow allowlist", because it is the owner's standing answer for generated projects; 0027 covers only this repo. `template/.claude/settings.json` is generated by `scripts/permissions/gen_settings.py` (profile `template`) and checked by `check_settings.py`: per-command allow rules only (auto mode drops blanket ones; no bare `git -C *`; bare `npm install` without package names), the ask-first list of AGENTS.md "Git and safety" as ask rules with `main`, `production`, `stage` and `dev` as core branches, and no deny rules. Whether generated projects should get the permissive policy instead is an open owner question.
- **Dogfood:** chosen option "a sync script with a manifest", because Windows symlinks are unreliable and hand-copying drifts. `dogfood.json` maps template sources to this repo's copies (folders copied recursively); `scripts/dogfood_check.py` fails on missing, differing or extra files and `--sync` fixes them. A source that does not exist yet passes. A mapped folder holds only template copies: `--sync` removes extra files, so repo-only agents or skills need a folder of their own.

### Consequences

- Good, because routine git, npm check and Backlog commands run without prompts in a generated project, while destructive git still asks.
- Bad, because writes under `.claude/` are protected paths: Claude Code never pre-approves them, so the owner may have to run `--sync` or approve profile and skill changes.
- Bad, because the allowlist is not a sandbox: `npm install` and `npm run check` run package scripts.
- Known residue: merging into a core branch other than `main` cannot be detected from the command, so it is an instruction-only rule; nested `template/.claude/skills` may appear twice in this repo once Claude reads files under `template/`.
