# Glossary

One word per concept, used the same way in code, UI, docs and conversations (the ubiquitous language of domain-driven design). Agents use these terms in names, add new terms when a concept appears, and flag synonyms instead of inventing new words.

| Term | Meaning | Not this | Context |
|---|---|---|---|

How much domain-driven design applies grows with the project:

- **Level 1, always:** this glossary.
- **Level 2, once a second business area exists:** add `docs/domain/contexts.md`, a map of the areas (bounded contexts) and which terms belong to which.
- **Level 3, only when complexity earns it:** tactical patterns (aggregates, value objects, domain events), each adopted through an architecture record in `docs/decisions/`.
